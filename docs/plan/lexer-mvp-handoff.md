## Goal

Implement the deliberately small C++ lexer profile needed to write the first
JSON parser in Joyeer. Self-hosting is not in scope.

The detailed design and test matrix are in
[../impl/lexer.md](../impl/lexer.md).

## Work completed in this WIP

### Documentation

- Added the detailed Lexer MVP contract and test matrix.
- Added Phase L before the larger ownership/data-model phases.
- Reduced the v0.1 JSON-parser surface to minimal `enum + match`, decimal
  integers, byte literals, fixed string escapes, `?`, and `&`.

### Token/source contract

- Added explicit terminal `TokenKind` values while retaining legacy category
  values temporarily for parser compatibility.
- Added `SourceSpan { offset, length }`.
- Added `startsLine`, 32-bit line/column fields, EOF, invalid, wildcard, and
  deferred-keyword tokens.
- Added keyword/operator/punctuation compatibility helpers.
- Added an in-memory `SourceFile` constructor and line-start offsets.

### Lexer implementation

- Replaced the iterator scanner with a byte-offset scanner.
- Added two profiles:
  - `legacy` (default);
  - `jsonParserMvp` selected by `--lang=v0.1`.
- Added reset-safe tokenization and exactly one EOF token.
- Added ASCII identifiers, MVP/deferred keyword classification, decimal
  integers, strings with fixed escapes, strict byte literals, nested block
  comments, line tracking, longest-match terminals, invalid-token recovery,
  and targeted lexical diagnostics.
- Unknown source bytes no longer disappear silently.

### Compatibility/integration

- Added `--lang=v0.1` and `--lang=v0.1-legacy` command-line modes.
- The existing parser temporarily accepts explicit terminal kinds through
  `tokenKindMatches()`.
- The parser stops at the new EOF token.
- Enabled the compiler unit-test directory and added direct lexer tests,
  including an acceptance source using the intended JSON-parser surface.

## Immediate engineering checklist

1. **Compile the new token/lexer API.** Fix compiler errors without expanding
   the MVP language surface.
2. **Make `CompilerLexerTests` link.** The test target may need additional
   Joyeer libraries because `CompileContext` and `SourceFile` transitively use
   runtime/compiler symbols.
3. **Run and correct all lexer tests.** Check string span lengths, malformed
   byte recovery, line numbers through nested comments, and exact diagnostic
   counts.
4. **Run legacy tests.** Legacy mode must continue recognizing class, `for`,
   division, `||`, force unwrap, and the existing octal-format diagnostics.
5. **Check string-literal compatibility.** The new lexer decodes escapes into
   `Token::rawValue`; verify IR/string-table behavior and legacy expected output.
6. **Check large integers.** `Token::intValue` is now `int64_t`; verify all
   bytecode and AST consumers compile and preserve `Int` width.
7. **Check EOF assumptions.** Any parser loop that assumed `tokens.end()` may
   need to recognize `endOfFile` explicitly.
8. **Check deferred syntax recovery.** In MVP mode each deferred construct
   should become one diagnostic plus one `invalid`/`deferredKeyword` token,
   never several misleading valid tokens.
9. **Do not implement enum/match parsing in this WIP unless lexer tests are
   green first.** Phase L should establish a stable token contract before the
   parser feature work begins.

## Known architectural compromises

- `Token::rawValue` and literal payloads are retained temporarily even though
  the final design prefers source spans without per-token lexeme allocation.
- Legacy broad categories (`keyword`, `punctuation`, `operators`) remain in the
  enum while parser call sites still use them.
- `TokenKind` is still an unscoped enum to minimize migration churn.
- Source line/column fields coexist with absolute spans during migration.
- The parser only has compatibility for new token kinds; it does not yet parse
  payload enums or `match`.
- `byteLiteral` is lexed and unit-tested but is not yet integrated into parser,
  type binding, or IR generation.
- MVP mode is opt-in through `--lang=v0.1`; default behavior remains legacy.

These compromises should be removed incrementally after the lexer and legacy
suite are green, not all at once.
