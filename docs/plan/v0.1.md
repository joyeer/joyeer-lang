# Joyeer v0.1 — Plan & Status

> Single source of truth for v0.1 scope and current state.
> This doc supersedes the former `v0.1-plan.md` and `v0.1-gaps.md`.
>
> v0.1 is **Phase 1** of [roadmap.md](roadmap.md). Long-term design commitments
> (memory model, call conventions, runtime budget) live under
> [../rationale/](../rationale/) and are out of scope here.

---

## Goal

A minimal language able to write a **zero-overhead JSON parser** in Joyeer,
performance-comparable to C / C++ / Rust.

A JSON parser exercises every minimum-viable language capability:

| Capability | Feature needed |
|---|---|
| Read string / file content | `String` + File I/O |
| Iterate bytes | byte indexing `s[i]: UInt8` + byte literals `b'x'` (spec §2.1.1) |
| Branch on `{`, `[`, `"` | `match` / `if-else` |
| Represent JSON values | `enum` (algebraic types) |
| Store key-value pairs | `Map<String, T>` |
| Store arrays | dynamic `Array<T>` |
| Recursive parsing | recursive functions |
| Report errors | `Result` / `Option` |
| Output results | `print` |

## Target Code (what should compile in v0.1)

> **Note.** The snippet below predates [spec.md](../spec.md) and uses pre-spec
> syntax (`Parser { ... }` literals, `case`/`default`, `charAt`, `Map`,
> `Number(Int)`). It illustrates the *capabilities* needed, not the canonical
> surface syntax — see [spec §16](../spec/16-examples.md) for spec-conformant
> examples (`match … =>`, struct call-construction, byte indexing).

```joyeer
enum JsonValue {
    Null,
    Bool(Bool),
    Number(Int),          // Int in the v0.1 milestone; spec §16.2 uses Double once Float/Double land
    Str(String),
    Array([JsonValue]),
    Object([String: JsonValue]),
}

enum JsonError {
    UnexpectedEof,
    Unexpected(UInt8, at: Int),
    InvalidNumber(String),
}

struct Parser {
    var input: String
    var pos: Int
}

// String is byte-indexed (spec §2.1.1): s[i] is the UInt8 at byte offset i,
// in O(1). JSON's structural characters are ASCII, so the parser matches on
// byte literals like b'"'. Code-point iteration (.chars()) is a v0.2 concern.
func peek(p: Parser): UInt8? {
    if p.pos >= p.input.count { return nil }
    return p.input[p.pos]
}

func advance(p: inout Parser): UInt8? {
    if p.pos >= p.input.count { return nil }
    let c = p.input[p.pos]
    &p.pos = p.pos + 1
    return c
}

func skipWhitespace(p: inout Parser) {
    while p.pos < p.input.count {
        let c = p.input[p.pos]
        if c != b' ' && c != b'\n' && c != b'\t' && c != b'\r' {
            return
        }
        &p.pos = p.pos + 1
    }
}

func parseValue(p: inout Parser): Result<JsonValue, JsonError> {
    skipWhitespace(p: &p)
    let c = match peek(p: p) {
        .Some(value) => value,
        .None => return .Err(.UnexpectedEof),
    }
    return match c {
        b'"'        => parseString(p: &p),
        b'{'        => parseObject(p: &p),
        b'['        => parseArray(p: &p),
        b't'        => parseBool(p: &p),
        b'f'        => parseBool(p: &p),
        b'n'        => parseNull(p: &p),
        _           => parseNumber(p: &p),
    }
}
```

Parameter passing follows [../rationale/parameter-passing.md](../rationale/parameter-passing.md):
`borrowing` (read-only) / `inout` (exclusive mutable) / `consuming` (ownership transfer).

### Nice to Have

- [x] File read (`readFile(path: String): Result<String, Int>`); binary-safe
    native success/error paths and ownership cleanup are tested
- [ ] `Float` / `Double`

### Out of Scope for v0.1

- **User-defined generics** (generic `func` / `struct` / `enum`, type
  parameters, constraints, monomorphization) — see the decision below
- Closures / lambdas
- `for-in` (use `while` in the first JSON parser)
- `||` (the first parser only requires `&&`; conditional logic can use `if` / `match`)
- `??`, `?.`, postfix propagation `?`, and force unwrap `!` (use explicit `match`)
- Compound assignment such as `+=` (use `x = x + 1`)
- Match guards, alternative/range patterns, and tuple destructuring
- Traits / protocols / interfaces
- Concurrency / async
- Module system (single file is enough for JSON parser)
- extending the legacy bytecode/VM backend; new code lowers toward Joyeer IR
    and a native backend
- **`break` / `continue`** (incl. labeled forms) and the `is` / `as`
  type-test / cast operators — deferred to v0.2 (spec §15); loops exit via
  their condition or `return`

## Decision: Generics in v0.1

**Short answer: no general generics in v0.1.** Split the concept in two:

| Kind | v0.1? | Why |
|---|---|---|
| **Built-in generic containers** — `Array<T>` (✅), `Map<K, V>` (partial) | ✅ Yes | Needed by the JSON parser. Implemented as **compiler/runtime-special-cased builtins**, *not* a general type-parameter mechanism. |
| **User-defined generics** — generic `func` / `struct` / `enum`, `<T>` declarations, constraints, monomorphization | ❌ No | The v0.1 target code (`JsonValue`, `Parser`) uses only **concrete types**. The JSON parser needs zero user-defined generics. |

Rationale:

- The [Target Code](#target-code-what-should-compile-in-v01) above defines no
  `<T>` of its own — `Array<JsonValue>` and `Map<String, JsonValue>` are
  *uses* of built-in containers, not new generic declarations.
- A real generic system (type-parameter inference, constraints, and
  zero-overhead monomorphization) is large and tightly coupled to the memory /
  runtime-overhead commitments in [../rationale/](../rationale/). Doing it early
  would stall the actual v0.1 blockers below.
- `Array<T>` / `Map<K, V>` therefore stay on the **hard-coded builtin** path:
  the angle brackets are container syntax the compiler understands directly,
  with no general type-parameter machinery behind them.

User-defined generics are deferred to **Phase 2/3** (see [roadmap.md](roadmap.md)).

## Critical Blockers (ordered for JSON parser)

The JSON parser cannot be written until the items below ship, in roughly
this order:

1. **Complete and execute the parser** — `readFile(path:)` supplies owned
    external bytes and dynamic array append works; dictionary insertion/update
    and an end-to-end native parser fixture remain.
2. **Finish source-level ownership conventions** — current values clone/move
    and destroy correctly, but `borrowing`, `consuming`, `initializing`, and
    `consume` flow states are not yet accepted by the v0.1 frontend.
3. **Optimization and diagnostics** — configure LLVM optimization and improve
    source rendering before calling v0.1 complete.

String escape scanning/decoding is complete, so embedded JSON objects such as
`"{\"n\":42}"` no longer block the lexer. Everything else can land after the
remaining items above.

The compiler lexer implements the deliberately small JSON-parser profile
defined in [../impl/lexer.md](../impl/lexer.md). That profile keeps
payload-carrying `enum` and `match`, but defers unrelated syntax sugar such as
`for-in`, match guards, range/alternative patterns, `??`, compound assignment,
interpolation, and the removed general effect syntax.

Phase L is complete. The remaining blockers above are frontend syntax/flow,
runtime library, backend policy, and diagnostic-quality work; lexical support
alone does not make a feature executable.

## Compiler Architecture Gaps

These block the **quality** of v0.1, not its feature set:

- [x] **Semantic analysis pass** — `let`/field immutability and access markers,
    all-paths-return, trailing-expression returns, unreachable warnings,
    definite initialization, and unused local/pattern warnings are enforced.
- [x] **Own IR (Joyeer IR)** — verified backend-neutral IR covers the JSON MVP.
- [x] **LLVM/native integration** — `--emit-llvm` and `-o` use Clang without
    constructing the legacy VM.
- [ ] **Diagnostics enhancement** — lexer errors now carry temporary zero-based
    line/column locations and support multi-error recovery, but stable IDs,
    file/span rendering, one-based display, and fix-it hints are missing.

## Runtime / Legacy VM Gaps

The native runtime is separate from these compatibility-VM gaps. It now has
recursive clone/destroy and deterministic compiler-inserted cleanup for the
current heap-backed surface; source-level consuming ownership remains open.

- [x] **Native memory reclamation MVP** — scope/early-return cleanup and the
    runtime allocation-balance check cover strings, arrays, dictionaries,
    nested aggregates, and tagged payloads.
- [ ] **`Debug` opcode decomposition** — bool formatting, `array.size()`,
      dict construction should be split into dedicated instructions.
